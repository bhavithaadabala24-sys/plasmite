The Problem Statement

FOLIO-01

Current production voice transcription pipelines depend strictly on proprietary cloud APIs, suffering from non-deterministic latency spikes (>300ms network round-trip) and acute data privacy liabilities. In extreme outdoor field laboratories, subterranean physics testbeds, and air-gapped university cleanrooms, full standalone operation is non-negotiable.

Project VAANI isolates an embedded speech-to-intent engine operating deterministically on low-power ARM architecture, processing continuous natural acoustics without telemetry backhaul or external DNS lookups.

Latency Ceiling < 140ms End-to-ear voice roundtrip
Power Budget 4.8 Watts Sustained peak inference
Footprint 1.42 GB Unified DRAM utilization

Pipeline Dataflow Architecture

POSIX C++20 / ONNX Runtime

The pipeline executes across three isolated POSIX real-time threads pinned to performance clusters, communicating via lockless shared-memory circular buffers.

Architectural Invariants

01.

Zero Network Permissions: The OS image compiles without network stack firmware. WPA supplicant and DHCP clients are completely excised from the init ramfs partition.

02.

Strict Real-Time Scheduling: The ALSA ingest loop runs isolated on CPU core 7 at SCHED_FIFO priority 85 to prevent audio buffer dropout under heavy NPU GEMM loads.

03.

Static Memory Allocation: All inference tensor arenas, context windows, and audio buffers are pre-allocated at startup. No runtime dynamic malloc() during the conversation loop.

Bug #02: Audio driver buffer underrun during beam search

SYMPTOM & IMPACT

Audio frames were dropped during speech decoding bursts, yielding severe phonetic hallucinations in the transcription transcript.

IDENTIFIED ROOT CAUSE

Thread priority inversion between low-level audio capture thread and high-concurrency ONNX inference worker on shared CPU cluster.

REMEDY & ARCHITECTURAL LESSON

Promoted ALSA capture thread to SCHED_FIFO priority 80 with dedicated core pinning to CPU Core 7. Configured 4-packet ring overflow buffer with zero dropped frames across a 4-hour test session.
